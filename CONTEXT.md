# Chesstopia — Domain Glossary

## Nutzer
A registered account with credentials, profile, and statistics. A Nutzer can be a Spieler, but not every Spieler is a Nutzer (guests and AI are also Spieler).

## Spieler
A participant in a Partie. Can be a [[Nutzer]], an AI, or (future) a guest. Always occupies one side (White or Black).

## Partie
A single chess game between two [[Spieler]]. Has a defined start position, an ordered sequence of [[Züge]], a result, and optionally a time control. A Partie can be ongoing or completed.

## Zug
A single half-move (ply) within a [[Partie]]. Stored as an immutable event record: SAN notation, the resulting [[FEN]] (Stellung after the move), timestamp, and time spent by the player (`time_spent_ms`). After engine analysis, also stores `centipawn_loss` and a move classification (BLUNDER / MISTAKE / INACCURACY / GOOD / EXCELLENT / BEST). The ordered sequence of all Züge in a Partie constitutes the Move-Event-Log from which any [[Stellung]] can be reconstructed and a [[PGN]] export derived.

## Stellung
The board state at any point in a [[Partie]], fully described by a [[FEN]] string (piece placement, side to move, castling rights, en-passant target, half-move clock, full-move number).

## FEN
Forsyth–Edwards Notation. The canonical serialization format for a [[Stellung]]. Used as the interchange format between the [[Schach-Engine]] and both frontend and backend.

## PGN
Portable Game Notation. The canonical serialization format for a complete [[Partie]] including metadata and the full [[Zug]] sequence. Used for storage and replay.

## Schach-Engine
The shared Kotlin Multiplatform library that is the single authoritative implementation of chess rules. Compiles to a JVM artifact (consumed by the backend) and a JS module (consumed by the frontend). Validates every [[Zug]] and produces legal-move lists for a given [[Stellung]].

## MoveEngine
An interchangeable backend component responsible for calculating the best [[Zug]] for a given [[Stellung]] and producing numeric [[Evaluation]] scores. The canonical implementation is Stockfish (server-side process, UCI protocol). Consumed only by the backend — never directly by the frontend.

## ChessCoach
An interchangeable backend component responsible for natural-language explanation of positions, move quality, and learning feedback. The canonical implementation is an LLM. Used by [[Trainingsmodus]] and the KI-assisted learning flow. Distinct from [[MoveEngine]]: does not generate moves, does not evaluate numerically.

## RatingSystem
An interchangeable backend component responsible for recalculating [[Nutzer]] ratings after a [[Partie]]. The canonical implementation is Glicko-2 (rating, rating deviation, volatility). Consumed only by the backend rating service. Distinct from [[MoveEngine]] and [[ChessCoach]].

## Rating
A numeric measure of a [[Nutzer]]'s playing strength, managed by the [[RatingSystem]]. Always stored with its associated uncertainty metric (e.g., rating deviation in Glicko-2). A Nutzer's Rating is updated after each rated [[Partie]].

## Evaluation
A numeric score produced by the [[MoveEngine]] for a given [[Stellung]], representing the advantage for White (positive) or Black (negative). Displayed as an Evaluation Bar in Analysis Mode. In live games the Evaluation Bar is driven by Stockfish.js running client-side (WASM); for post-game analysis it is computed server-side.

## Lernpfad
A personalized learning plan generated by [[ChessCoach]] (LLM) for a [[Nutzer]]. Analyzes the Nutzer's game history, [[Trainingsposition]] results, and [[Tutorial]] completion to identify weaknesses and recommend the next [[Trainingsposition]]en and [[Tutorial]]s to work on. Adapts as the Nutzer's skills evolve.

## Tutorial
A structured guided lesson generated by [[ChessCoach]] (LLM) that teaches a chess concept (e.g., forks, pins, discovered attacks). Consists of a sequence of [[Stellung]]en with explanations; the Nutzer executes predefined moves to experience the concept rather than finding the best move independently. Distinct from [[Trainingsmodus]]: the goal is understanding, not tactical solving.

## Trainingsmodus
A mode in which a [[Nutzer]] is presented with a [[Trainingsposition]] and asked to find the best continuation. After completing the puzzle, a natural-language explanation is shown. Distinct from a free [[Partie]].

## Trainingsposition
A chess puzzle consisting of a [[Stellung]] (FEN), the engine-computed best solution (calculated by [[MoveEngine]]), difficulty level, and topic tags. Two sources: (1) automatically extracted from asynchronously analyzed [[Partien]] when the engine detects a significant tactical opportunity or blunder; (2) imported from the Lichess open puzzle database. Persisted permanently. When a [[Nutzer]] attempts a Trainingsposition, their move sequence is evaluated by [[MoveEngine]]; [[ChessCoach]] (LLM) then provides a natural-language explanation of the user's choices relative to the best line. Nutzer progress (solved/unsolved) is tracked per Trainingsposition.

## Design
A user-customizable visual configuration consisting of a Figuren-Sprite-Set (12 SVG/PNG piece images, server-side sanitized on upload) and Farb-Tokens (board light/dark square colors and highlight colors, configured via color picker). Designs are owned by a [[Nutzer]] and can be applied to any [[Partie]]. Full CSS uploads are not supported.

## RuleSet
A configuration object attached to a [[Partie]] that defines which chess rules are active. Consists of a base Variant (e.g., Standard, Chess960, King of the Hill, Three-Check) plus a set of optional rule Toggles (e.g., disable en passant). The [[Schach-Engine]] receives the RuleSet and applies it during move validation. Arbitrary scripted or free-form rules are out of scope.

## Variant
A named, well-known chess rule configuration (e.g., Standard, Chess960, King of the Hill, Three-Check, Crazyhouse) used as the base of a [[RuleSet]].

## Zeitkontrolle
A predefined time control configuration attached to a [[Partie]]. Stored as a system-managed preset with a display name, initial time in seconds, and increment in seconds. "Ohne Zeit" is represented as a special preset with no timer. Players select from available presets when creating a Partie; arbitrary custom values are not supported.

## Sichtbarkeit
A property of a [[Partie]] determining who can view it. Values: PRIVATE (visible only to the participating [[Spieler]]) or PUBLIC (visible to all). Any Partie can additionally have a share_token — a randomly generated token that grants read access to anyone who holds it, regardless of visibility setting.

## Direkteinladung
A game-creation mode where a [[Nutzer]] creates a [[Partie]] and receives a shareable join-link. Any person with the link can join, regardless of whether they have an account. The opponent is not known in advance.

## Nutzer-Challenge
A game-creation mode where a [[Nutzer]] sends a challenge notification to a specific registered [[Nutzer]]. The recipient can accept or decline. Both parties must be registered.

## Turnier
An organized competition between multiple [[Nutzer]] consisting of multiple [[Partien]] governed by tournament rules. Any registered [[Nutzer]] may create a Turnier. Initial supported format: K.O. (single-elimination bracket). Further formats (Swiss, Arena, Round Robin) are deferred.
